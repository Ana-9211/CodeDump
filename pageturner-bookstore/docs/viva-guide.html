🏗 Design
Why did you split data between PostgreSQL and MongoDB?
Picture itThink of a bank counter and a suggestion box. Money and stock need a counter where everything is checked and recorded together (PostgreSQL transactions). Reviews are free-form notes dropped in a box: flexible, many of them, never added up with money (MongoDB).
Say thisBecause the *shape* of the data differs: orders need ACID and foreign keys; reviews are self-contained documents with an array of voters. The only link is the numeric id, plus a cached rating summary.
Why store money as integers?
Picture itLike counting paise in a coin jar instead of weighing the coins: no rounding errors.
Say thisfloat cannot represent 0.1 exactly, so totals drift. Integers of paise are exact and sum correctly.
Why copy the title and price into order_items?
Picture itA printed receipt does not change when the shop changes its price tomorrow.
Say thisIt is a historical fact, not redundant data. Without it, repricing a book would silently rewrite past invoices. Same for the shipping address.
Show normalization.
Picture itWrite each fact on exactly one card.
Say thisAuthors moved out of books into authors + book_authors (1NF/M:N). Category name lives only in categories (3NF). Every determinant in the main tables is a candidate key, so they are BCNF. Documented exceptions: snapshots and avg_rating cache.
🔐 Security & roles
Where is role-based access enforced?
Picture itA hotel key card: GRANT is the floor, Row Level Security is the room, the front desk (stored procedure) checks your ID.
Say thisInside PostgreSQL, not only in JavaScript. The app logs in as bookstore_app and runs SET LOCAL ROLE per request, so even an application bug cannot read another user's order.
Why SET LOCAL and not SET?
Picture itA visitor badge that expires when you leave the building.
Say thisSET LOCAL lasts only for the current transaction, so a pooled connection cannot carry one user's identity to the next request.
What is SECURITY DEFINER and is it dangerous?
Picture itA bank clerk who can open the vault *for you*, only after checking your ID.
Say thisThe function runs with its owner's privileges so it can write several tables the caller cannot touch. Safe because each one starts with fn_require_role(...), fixes search_path, and EXECUTE is revoked from PUBLIC.
How do you stop SQL injection?
Picture itNever gluing words into a sentence the database will obey.
Say thisEvery value is a bound parameter ($1, $2). The only interpolated pieces (sort column, role name) come from fixed whitelists.
How are passwords and reset links protected?
Picture itWe keep only a fingerprint, never the password or the key.
Say thisbcrypt hashes; reset tokens are random 32 bytes, only their SHA-256 is stored, they expire in 30 minutes and work once. The reply for unknown e-mails is identical.
⚙️ Transactions & concurrency
Two customers click Buy on the last copy at the same moment. What happens?
Picture itTwo people grabbing the last cake: the shop assistant lets one hold it while the other waits, then tells the second 'sorry, gone'.
Say thissp_place_order locks the book rows with SELECT … FOR UPDATE in a fixed order (no deadlocks). The second transaction waits, then sees stock 0 and raises an error, rolling back completely. There is a test that races them.
What does 'atomic' mean for checkout?
Picture itA vending machine: either you get the snack and it takes your coin, or nothing happens.
Say thisOrder, lines, payment, stock deduction and cart clearing are one transaction. If any step fails, all roll back.
Why triggers for stock and status?
Picture itA door that locks itself, instead of a sign asking people to close it.
Say thisRules like 'stock never negative' and 'Placed → Packed → Shipped → Delivered only' hold no matter which code path writes the data.
🔎 Queries
Explain your recursive CTE.
Picture itFinding all the descendants in a family tree: start with the roots, then repeatedly add children.
Say thisfn_category_tree starts with rows where parent_id IS NULL and UNION ALL joins children to what has been found so far, building depth and path. Used for the catalogue filter (a category includes its sub-categories).
Correlated vs nested subquery?
Picture itNested: look up one number once. Correlated: ask the question again for each row.
Say thisprice > (SELECT avg(price) FROM books WHERE category_id = b.category_id) re-evaluates per book. See advanced_queries.sql #1 and #3.
Window function example?
Picture itA running scoreboard instead of just the final score.
Say thisSUM(revenue) OVER (ORDER BY day) in fn_sales_report gives the cumulative revenue line; RANK() OVER ranks sellers in v_seller_performance.
🍃 MongoDB
Show create / read / update / delete in MongoDB.
Picture itIndex cards in a box: add, look up, edit, tear up.
Say thisCreate insertOne (validator + unique index), Read find().sort().skip().limit() and aggregate([$group]), Update findOneAndUpdate($set) and updateOne($addToSet/$inc) for votes, Delete findOneAndDelete. Run npm run nosql:demo.
What is the TTL index for?
Picture itA sticky note that peels off by itself after a month.
Say thisbook_views documents expire after 30 days automatically, so the click-stream never grows forever.
What if MongoDB is down?
Picture itThe shop keeps selling; only the review box says 'unavailable'.
Say thisReviews are isolated behind one service; errors map to HTTP 503 and the pages degrade gracefully.
30-second pitch. One bookstore, two databases chosen on purpose: PostgreSQL for money, stock and identity (transactions, triggers, procedures, Row Level Security so roles are enforced by the database itself) and MongoDB for flexible, write-heavy reviews and view events. Next.js gives the interface and API. Everything is tested: 91 automated tests including a concurrency race for the last copy.
